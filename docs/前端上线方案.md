# 前端上线方案（P2-4）

目标：把 `frontend/` 这个纯静态页面，从「只能在本机跑」变成「能给别人点开用」。

## 一、先说结论

| 场景 | 方案 | 成本 | 门槛 |
|------|------|------|------|
| 自己看、演示 | 本机 `node frontend/serve.js` | 0 | 一条命令（已验证可用） |
| 给别人公网访问 | Vercel 连 GitHub 仓库 | 0 | 注册 Vercel，点几下 |
| 备选 | GitHub Pages（单独公开仓库） | 0 | 会多一个公开仓库 |

前端里没有任何秘密：只有合约地址、ABI、公开的 Sepolia RPC 地址。放公网不会泄露私钥。
（私钥从头到尾只在 `.env` 里，且 `.env` 不会被这两个方案上传——Vercel 只构建 `frontend/`，Pages 只放 frontend 内容。）

## 二、本机预览（已验证）

```powershell
cd frontend
node serve.js
```

浏览器打开 http://localhost:5173

为什么不能直接双击 `index.html`：浏览器在 `file://` 协议下禁止页面用 fetch 读同目录的 `abi/*.json`，
页面会拿到空白 ABI，功能全部失效。所以必须走 `http://`。

停止服务：在该窗口按 `Ctrl + C`。

## 三、方案 A：Vercel（推荐，支持私有仓库）

1. 浏览器打开 https://vercel.com ，用 GitHub 账号登录（GitHub 账号你已经有）
2. 点 **Add New → Project**，导入你刚建的那个仓库
3. 关键设置：
   - **Root Directory** 填 `frontend`（只构建前端目录，合约和 .env 不参与）
   - Framework Preset 选 **Other**
   - Build Command 留空（纯静态，不需要构建）
4. 点 Deploy，约十几秒后拿到 `https://xxx.vercel.app`

之后每次把代码推到 GitHub，Vercel 会自动重新部署。

## 四、方案 B：GitHub Pages（免费账号只能公开仓库）

免费账号的 Pages 不支持私有仓库，所以做法是：

1. 新建一个**公开**仓库，例如 `simplemarket-frontend`
2. 只把 `frontend/` 目录里的内容（index.html、app.js、config.js、abi/、vendor/）传上去，放在仓库根目录
3. 仓库 Settings → Pages → Source 选 `Deploy from a branch` → 分支 `main`、目录 `/ (root)` → Save
4. 几分钟后访问 `https://<你的用户名>.github.io/simplemarket-frontend/`

注意：不要把整个项目（含 `.env`）传进这个公开仓库。

## 五、上线前要检查的三件事

1. **MetaMask 连接**：非 localhost 的 `http://` 站点，MetaMask 不注入。Vercel / Pages 都自带 HTTPS，没这个问题。
2. **网络**：页面要连 Sepolia，用户在墙内访问公共 RPC（publicnode）可能偏慢或抽风。
   真要对外用，建议去 Alchemy / Infura 申请免费 Key，把 `frontend/config.js` 里的 `rpcUrl` 换成带 Key 的地址，
   然后跑 `npx hardhat run scripts/gen-frontend-config.js` 重新生成（改 .env 里的 `SEPOLIA_RPC_URL` 再生成）。
3. **合约已验证**：别人在 Etherscan 上看到的是未验证字节码，会不信任。
   Etherscan 验证走 GitHub Actions 那一步完成后，页面里可以放心把合约链接放出去。

- 部署记录、ABI、前端配置四合约地址已同步（见 `frontend/config.js`）
